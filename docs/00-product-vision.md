# 00 - Product Vision
# چشم‌انداز محصول فارم نت

## 1. معرفی محصول

«فارم نت» یک سوپراپلیکیشن جامع کشاورزی است که با هدف اتصال کشاورزان، فروشگاه‌ها، موجران ادوات کشاورزی، خدمات‌دهندگان، مشاوران، شرکت‌ها و کاربران عادی در یک اکوسیستم واحد طراحی می‌شود.

این پلتفرم قرار است نیازهای اصلی حوزه کشاورزی را در قالب یک اپلیکیشن چندبخشی پوشش دهد؛ از خرید و فروش محصولات کشاورزی تا اجاره ادوات، دریافت خدمات، مشاوره تخصصی، آب‌وهوا، هوش مصنوعی، فضای اجتماعی، تبلیغات، اشتراک و دسترسی داده برای شرکت‌ها.

---

## 2. هدف اصلی پروژه

هدف اصلی «فارم نت» ایجاد یک بستر پایدار، قابل توسعه و درآمدزا برای فعالان حوزه کشاورزی است.

کاربر باید بتواند در این پلتفرم:

- محصول کشاورزی پیدا کند.
- فروشگاه ثبت کند.
- ادوات کشاورزی را اجاره دهد یا اجاره کند.
- خدمات کشاورزی دریافت یا ارائه کند.
- از مشاوران تخصصی کمک بگیرد.
- هشدارهای آب‌وهوایی و اطلاعات منطقه‌ای دریافت کند.
- از هوش مصنوعی برای پرسش‌های کشاورزی استفاده کند.
- در فضای اجتماعی کشاورزی فعالیت کند.
- از طریق نوتیفیکیشن در جریان وضعیت درخواست‌ها، مدارک، فاکتورها، پرداخت‌ها و هشدارها قرار بگیرد.

## 3. نوع محصول

نوع محصول:

```text
Agriculture Super App
```

یعنی پروژه فقط یک فروشگاه یا فقط یک اپ مشاوره نیست.
این پروژه یک پلتفرم چندبخشی است که بخش‌های مختلف کشاورزی را به هم متصل می‌کند.

## 5. قانون اصلی هویت کاربر

در این سیستم، User به معنی فروشنده، مشاور یا موجر نیست.

```text
User = حساب اصلی شخص
```

هر کاربر ابتدا یک حساب رایگان و پروفایل پایه دارد.
بعداً می‌تواند درخواست فعالیت حرفه‌ای بدهد.

فعالیت‌های حرفه‌ای ممکن:

```text
1. ثبت فروشگاه
2. موجر شدن برای اجاره ادوات کشاورزی
3. خدمات‌دهنده شدن
4. مشاور شدن
5. همکاری محتوایی
6. دریافت دسترسی داده به عنوان شرکت طرف قرارداد
```

فعالیت حرفه‌ای فقط پس از طی این مراحل فعال می‌شود:

```text
ثبت‌نام
→ ساخت پروفایل رایگان
→ درخواست فعالیت حرفه‌ای
→ ارسال مدارک
→ پذیرش قرارداد
→ آپلود قرارداد PDF در صورت نیاز
→ بررسی ادمین
→ تأیید
→ فعال شدن پنل مربوطه
```

## 6. زبان، تم، تاریخ و پول

پلتفرم باید از ابتدا دو زبانه باشد:

```text
Persian / fa
English / en
```

تم‌ها:

```text
Light
Dark
```

قوانین نمایش در حالت فارسی:

```text
اعداد فارسی
تاریخ شمسی
واحد پول تومان
چیدمان راست‌به‌چپ
```

قوانین ذخیره‌سازی در Backend:

```text
تاریخ‌ها به صورت UTC/Gregorian ذخیره می‌شوند.
قیمت‌ها به صورت عدد خام تومان ذخیره می‌شوند.
اعداد در دیتابیس و API به صورت raw numeric هستند.
نمایش فارسی، شمسی و تومان در Frontend انجام می‌شود.
```

## 7. مدل درآمدی پروژه

درآمد پروژه از چند مسیر اصلی تأمین می‌شود:

```text
1. کمیسیون از فاکتورهای نهایی
2. اشتراک Pro
3. تبلیغات / نردبان
4. دسترسی داده کنترل‌شده برای شرکت‌ها
```

### 7.1 کمیسیون

کمیسیون هنگام صدور فاکتور نهایی محاسبه می‌شود.

مثال:

```text
مبلغ فاکتور: ۱,۰۰۰,۰۰۰ تومان
کمیسیون پلتفرم: ۱۰٪
سهم پلتفرم: ۱۰۰,۰۰۰ تومان
سهم فروشگاه/موجر/مشاور: ۹۰۰,۰۰۰ تومان
```

قانون مهم:

```text
مقدار کمیسیون در زمان صدور فاکتور snapshot می‌شود.
اگر بعداً ادمین درصد کمیسیون را تغییر دهد، فاکتورهای قبلی نباید تغییر کنند.
```

### 7.2 اشتراک Pro

اشتراک Pro برای امکانات بیشتر استفاده می‌شود، نه به جای کمیسیون.

نمونه امکانات Pro:

```text
ثبت محصول بیشتر
نمایش بهتر
گزارش بازدید
امکانات بیشتر پنل
دسترسی بیشتر به AI
دریافت درخواست بیشتر برای مشاوران
```

### 7.3 تبلیغات / نردبان

فروشگاه، محصول، خدمت، تجهیز یا مشاور می‌تواند با تبلیغات یا نردبان در جایگاه بالاتر نمایش داده شود.

تبلیغ نباید داده اصلی را تغییر دهد.
فقط روی رتبه نمایش اثر می‌گذارد.

### 7.4 دسترسی داده

دسترسی داده باید کنترل‌شده، قراردادی، سطح‌بندی‌شده و لاگ‌شده باشد.

داده‌های حساس مثل شماره موبایل، مدارک، قراردادها و آدرس دقیق نباید بدون قانون و کنترل در اختیار شرکت‌ها قرار بگیرد.

## 9. نوتیفیکیشن

نوتیفیکیشن یکی از هسته‌های اصلی سیستم است.

کانال‌های موردنیاز:

```text
1. In-App Notification
2. Push Notification
3. SMS
4. Email
```

هر رویداد لازم نیست از همه کانال‌ها ارسال شود.
کانال ارسال باید براساس اهمیت رویداد تعیین شود.

مثال:

```text
OTP:
SMS

تأیید فروشگاه:
In-App + Push + Email

صدور فاکتور:
In-App + Push + Email

پرداخت موفق:
In-App + Push + SMS یا Email

هشدار آب‌وهوایی مهم:
Push + In-App + SMS در صورت ضرورت
```

## 11. اصول کلیدی محصول

اصول کلیدی که باید در کل پروژه رعایت شود:

```text
1. پروژه باید مرحله‌ای ساخته شود.
2. هر بخش ابتدا در حد Core کامل شود.
3. همه بخش‌ها باید قابل تست و مستند باشند.
4. هر عملیات مهم باید Audit Log داشته باشد.
5. هر بخش مهم باید Notification Event داشته باشد.
6. هیچ داده حساسی بدون کنترل و مجوز نباید قابل دسترسی باشد.
7. UI باید فارسی/انگلیسی، ریسپانسیو، دارک/لایت و سازگار با اعداد فارسی و تاریخ شمسی باشد.
8. Backend باید داده خام و استاندارد ذخیره کند.
9. Frontend باید نمایش محلی‌سازی‌شده انجام دهد.
10. پروژه باید با Git، مستندات، بکاپ و Definition of Done کنترل شود.
```

## 12. هدف نسخه اول

هدف نسخه اول ساختن کل سوپراپ کامل نیست.

هدف نسخه اول این است:

```text
ساخت ستون فقرات پایدار پلتفرم
پیاده‌سازی هویت، نقش‌ها، جغرافیا، نوتیفیکیشن، مدارک، قرارداد، ادمین، اشتراک، کمیسیون، پرداخت پایه، فروشگاه و پنل فروشگاه
```

بخش‌هایی مثل AI، Social، Services، Consultants، Weather و Data Access در نسخه‌های بعدی به شکل Core اضافه می‌شوند.

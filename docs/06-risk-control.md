# کنترل ریسک‌های پروژه فارم نت

## 1. هدف سند

این سند برای شناسایی، پیشگیری و کنترل ریسک‌های پروژه «فارم نت» نوشته شده است.

پروژه «فارم نت» یک سوپراپلیکیشن بزرگ، چندتیمی و چندماژولی است. بنابراین ریسک‌های آن فقط فنی نیستند؛ شامل ریسک‌های محصول، تیم، دیتابیس، پرداخت، نوتیفیکیشن، امنیت، بکاپ، مستندات و انتشار هم می‌شود.

هدف این سند این است که پروژه دوباره دچار این مشکلات نشود:

```text
گم شدن مسیر پروژه
نیمه‌کاره ماندن ماژول‌ها
ناهماهنگی تیم‌ها
APIهای ناسازگار
دیتابیس شلخته
نبود بکاپ
پرداخت ناپایدار
نوتیفیکیشن پرهزینه
نبود تست
نبود مستندات
انتشار نسخه خراب
```

# 2. قانون اصلی کنترل ریسک

قانون اصلی:

```text
هر ریسکی که از قبل قابل پیش‌بینی است، نباید بعداً تبدیل به بحران شود.
```

برای هر ریسک باید این‌ها مشخص باشد:

```text
1. ریسک چیست؟
2. چرا خطرناک است؟
3. نشانه‌های وقوع آن چیست؟
4. چطور پیشگیری می‌کنیم؟
5. اگر اتفاق افتاد چه واکنشی داریم؟
```

---

# 3. سطح‌بندی ریسک‌ها

ریسک‌ها از نظر شدت به سه سطح تقسیم می‌شوند:

```text
Low:
قابل کنترل، اثر محدود

Medium:
اثر جدی روی یک ماژول یا یک تیم

High:
اثر جدی روی کل پروژه، زمان‌بندی، امنیت یا درآمد
```

ریسک‌های High باید در جلسه هفتگی بررسی شوند.

# 27. نتیجه

کنترل ریسک در پروژه «فارم نت» یک کار جانبی نیست.
بخشی از خود توسعه است.

```text
پروژه‌ای که ریسک‌هایش مدیریت نشود، حتی با کد خوب هم شکست می‌خورد.
```

برای جلوگیری از تکرار مشکل قبلی، هر فاز باید همراه با این سه چیز تحویل شود:

```text
1. کد
2. تست و مستندات
3. کنترل ریسک و بکاپ
```
